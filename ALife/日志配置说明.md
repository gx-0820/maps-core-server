# 日志配置说明

## 概述

本项目已配置完整的日志系统，支持控制台输出和文件持久化存储。

## 配置文件

### 1. logback-spring.xml（默认/开发环境）
- **位置**: `src/main/resources/logback-spring.xml`
- **适用场景**: 开发、测试环境
- **日志级别**: INFO
- **日志路径**: `./logs/`（项目根目录下的 logs 文件夹）

### 2. logback-spring-prod.xml（生产环境）
- **位置**: `src/main/resources/logback-spring-prod.xml`
- **适用场景**: 生产环境
- **日志级别**: WARN（根日志）、INFO（业务日志）
- **日志路径**: `/var/log/core-server/`（可通过环境变量 `LOG_PATH` 覆盖）

## 日志文件说明

启动后会在日志目录下生成以下文件：

| 文件名 | 说明 | 保留策略 |
|--------|------|----------|
| `core-server.log` | 所有INFO及以上级别的日志 | 30天，最大10GB |
| `core-server-error.log` | 仅ERROR级别日志 | 30-90天，最大5-10GB |
| `core-server-business.log` | 业务逻辑相关日志 | 30-60天，最大5-10GB |
| `core-server-grpc.log` | gRPC通信日志 | 15-30天，最大2-5GB |
| `core-server-websocket.log` | WebSocket通信日志 | 15-30天，最大2-5GB |

**滚动策略**:
- 单个文件最大: 50-100MB
- 按日期和大小自动分割
- 超过容量限制自动删除最旧日志

## 使用方式

### 开发环境启动
```bash
mvn spring-boot:run
```
日志会输出到控制台和项目根目录的 `logs/` 文件夹。

### 生产环境启动
```bash
# 方式1: 使用生产配置文件
java -jar core-server.jar --spring.profiles.active=prod --logging.config=classpath:logback-spring-prod.xml

# 方式2: 通过环境变量指定日志路径
LOG_PATH=/var/log/myapp java -jar core-server.jar
```

### Docker 环境
Docker 环境的日志配置在 `application-docker.yml` 中：
- 日志路径: `/app/logs/`
- 建议在 docker-compose.yml 中挂载日志卷：
```yaml
volumes:
  - ./logs:/app/logs
```

## 日志级别说明

| 级别 | 说明 | 使用场景 |
|------|------|----------|
| ERROR | 错误信息 | 系统异常、业务失败 |
| WARN | 警告信息 | 潜在问题、降级处理 |
| INFO | 一般信息 | 关键业务流程、重要状态变更 |
| DEBUG | 调试信息 | 详细执行过程（开发环境） |
| TRACE | 追踪信息 | 最详细的调试信息 |

## 代码中使用日志

项目中已集成 Lombok 的 `@Slf4j` 注解，在类上添加即可使用：

```java
@Slf4j
@RestController
public class ExampleController {
    
    @GetMapping("/example")
    public Result example() {
        log.info("开始处理请求");
        try {
            // 业务逻辑
            log.debug("调试信息: {}", variable);
            return Result.success();
        } catch (Exception e) {
            log.error("处理失败", e);
            return Result.error("处理失败");
        }
    }
}
```

**日志方法**:
- `log.trace()` - 追踪级别
- `log.debug()` - 调试级别
- `log.info()` - 信息级别
- `log.warn()` - 警告级别
- `log.error()` - 错误级别

**最佳实践**:
```java
// ✅ 推荐：使用占位符
log.info("用户 {} 登录成功，IP: {}", username, ipAddress);

// ❌ 不推荐：字符串拼接
log.info("用户 " + username + " 登录成功，IP: " + ipAddress);

// ✅ 推荐：异常日志包含堆栈
log.error("数据库操作失败", exception);

// ✅ 推荐：关键业务节点记录日志
log.info("无人机 {} 起飞，位置: ({}, {})", droneId, lat, lon);
```

## 日志查看

### Linux/Mac
```bash
# 实时查看日志
tail -f logs/core-server.log

# 查看错误日志
tail -f logs/core-server-error.log

# 搜索特定内容
grep "ERROR" logs/core-server.log
grep "无人机" logs/core-server-business.log
```

### Windows PowerShell
```powershell
# 实时查看日志
Get-Content logs\core-server.log -Wait -Tail 50

# 查看错误日志
Get-Content logs\core-server-error.log -Wait

# 搜索特定内容
Select-String "ERROR" logs\core-server.log
```

## 性能优化

1. **异步日志**: 文件输出采用异步方式，减少IO阻塞
2. **日志分级**: 不同模块输出到不同文件，便于排查
3. **自动清理**: 基于时间和大小的滚动策略，避免磁盘占满
4. **生产环境优化**: 
   - 关闭SQL日志
   - 第三方库日志设为WARN
   - 增大队列大小提高吞吐量

## 注意事项

1. ⚠️ **不要提交日志文件到Git** - 已在 `.gitignore` 中配置
2. ⚠️ **生产环境定期检查磁盘空间** - 虽然配置了自动清理，但仍需监控
3. ⚠️ **敏感信息脱敏** - 不要在日志中记录密码、token等敏感信息
4. ⚠️ **避免频繁打印大对象** - 会影响性能和日志文件大小
5. ⚠️ **生产环境不要开启DEBUG级别** - 会产生大量日志影响性能

## 故障排查

### 问题1: 没有生成日志文件
- 检查应用是否正常启动
- 确认日志目录是否有写权限
- 查看控制台是否有Logback初始化错误

### 问题2: 日志文件过大
- 检查滚动策略配置
- 确认 `maxFileSize` 和 `totalSizeCap` 设置合理
- 手动清理旧日志文件

### 问题3: 日志不输出
- 检查日志级别配置
- 确认使用了正确的日志配置文件
- 验证 `@Slf4j` 注解是否正确添加

## 自定义配置

如需调整日志配置，修改对应的 `logback-spring*.xml` 文件：

```xml
<!-- 修改日志级别 -->
<logger name="com.example.coreserver" level="DEBUG"/>

<!-- 修改日志路径 -->
<property name="LOG_PATH" value="/custom/log/path"/>

<!-- 修改保留天数 -->
<maxHistory>90</maxHistory>
```

修改后重启应用生效。
